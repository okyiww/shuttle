# 需求点提取

## 适用场景

用户是需求翻译官：原始需求来自外部（开会、聊天、截图），他的工作是消化素材、建成 Jira 任务。本 skill 负责流水线第一棒：**素材 → 候选需求点清单**。用户做审稿人，不做被采访者。

## 输入

- 会议转录（voicenotes 拉取或粘贴）
- 聊天记录（文本粘贴或截图 OCR 结果）
- 任何"别人说的原话"形式的素材

## 流程

1. **通读素材**，识别所有潜在需求信号：明确请求、抱怨痛点、反复提及的问题、"能不能/要不要/最好"句式、决策中隐含的待办
2. **区分三类信息**，只把第一类放进候选清单：
   - 需求点（要做什么）→ 进清单
   - 决策/结论（定了什么）→ 单独列出，不建任务
   - 行动项（谁什么时候做什么）→ 单独列出，可建子任务
3. **逐条标注置信度和缺口**：素材里没说清的（验收标准、涉及系统、优先级、量级），明确标成缺口，不要编造
4. **每条附原话引用**：会议素材标"会议名/日期 + 大致时间点 + 发言人原话"；聊天素材标"日期 + 发言人 + 原句"。这是溯源依据，被挑战时拿得出原文
5. 输出候选清单，等待用户确认、补充、删除，**不要急着建任务**

## 输出模板

```markdown
## 候选需求点（按优先级建议排序）

### 1. <一句话标题>
- **需求描述**：<从素材归纳的一句话>
- **置信度**：高/中/低（低 = 只是暗示，需要确认）
- **缺口**：<素材里没说清、需要补的字段，如"验收标准缺失""影响系统不明">
- **来源**：<会议 9/22 约 23:15，张三："原话引用"> 或 <微信 9/21，李四："原话引用">
- **优先级建议**：高/中/低 + 一句理由

### 2. <下一个…>

## 决策与结论（不建任务，仅记录）
- <会议定了什么，原话引用>

## 行动项（可另立任务）
- <谁、做什么、何时、原话引用>
```

## 质检清单（输出前自检）

- [ ] 每条需求都有原话引用和来源定位？
- [ ] 缺口都显式标出了，没有替需求方编造细节？
- [ ] 需求/决策/行动项三类分开，没有混在一起？
- [ ] 低置信度条目明确标注，等待用户确认而非自行放大？
