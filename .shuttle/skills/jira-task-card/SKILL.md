# 任务卡规范化

## 适用场景

流水线的第二棒：候选需求点已经用户确认、缺口已补齐，现在把每条点变成**可直接创建的标准 Jira 任务**。产出物是给人最后拍板的卡片，字段固定、带来源引用。

## 输入

- 已确认的需求点（来自 extract-requirement-candidates 的清单，或用户直接描述）
- 补全后的缺口信息（验收标准、范围、优先级）

## 流程

1. **缺字段先问**：确认后的点若仍缺验收标准或范围，先补问，不要带缺建卡
2. **按输出模板逐条生成任务卡片**，描述控制在 5 行以内，细节放验收标准
3. **来源引用必须原样保留**（来自提取阶段），这是溯源依据
4. **查重建议**：通过 Atlassian MCP 用 JQL 按关键词搜一下是否已有同类 issue，有则提示用户是新建还是关联已有
5. 卡片交给用户最终确认；用户说"建"之后，再通过 Atlassian MCP 的创建操作逐条创建，返回 issue key 和链接

## 输出模板（每条需求一张卡）

```markdown
### 任务卡：<标题，动词开头，≤ 20 字>

- **标题**：<动词 + 对象 + 关键约束>
- **背景**：<2-3 句话：谁在什么场景遇到什么问题，来源是什么>
- **验收标准**：
  - <可测试的条件 1>
  - <可测试的条件 2>
  - <可测试的条件 3>
- **范围外**（明确不做什么）：
  - <非目标 1>
- **来源**：<会议/聊天 + 日期 + 原话引用>
- **优先级建议**：<高/中/低 + 一句理由>
- **建议 Assignee**：<素材里提到的人，或留空让用户定>
```

## 质检清单（输出前自检）

- [ ] 每个验收标准都是可测试的（不是"优化""提升"这类不可测词）？
- [ ] 范围外至少有一条，明确非目标？
- [ ] 来源引用原话完整，能直接回溯？
- [ ] 创建前做了查重提示？
- [ ] 描述里没有替需求方编造素材中不存在的细节？
